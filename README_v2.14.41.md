# AI Remote Control GPT v2.14.41 — защищённый вход в приложении

## Результат аудита

В установленной v2.14.40 на скриншоте показано `CLOUD_SESSION_NO_SESSION`: сохранённого подтверждённого OAuth-сеанса нет. Это **следствие** неуспешного завершения входа, а не самостоятельный диагноз DNS. Ранее в v2.14.39 наблюдался `AUTH_TOKEN_DNS_FAILURE`; по одним скриншотам нельзя гарантированно установить причину каждого сетевого сбоя. Предварительный HTTPS-ответ 200 с auth.openai.com не доказывает доступность следующего OAuth POST.

## Исправления

1. `ChatGptCloudBridge.startSignIn`: вместо запуска отдельного Chrome через `ACTION_VIEW` основной путь теперь **AndroidX Browser Custom Tabs**. Это видимый внутри приложения интерфейс **браузера OpenAI**, не самодельная форма пароля. Логин и 2FA вводятся только на официальном `auth.openai.com`. При отсутствии Custom Tabs остаётся безопасный внешний браузер.
2. Ожидание обратного вызова увеличено с 180 до **600 секунд** для обычного входа с 2FA и согласиями. Сохранены привязка к `127.0.0.1`, проверка state и nonce и PKCE S256.
3. Если подключение к `auth.openai.com` обрывается на `UnknownHostException` **до отправки OAuth-кода**, допускается одна попытка установить соединение через DNS активной Android-сети (`ConnectivityManager.activeNetwork.openConnection`) вместо повторения того же системного пути. Не меняются TLS-проверка, hostname, URL и подпись токена. При отсутствии активной сети используется прежний путь. **Код после отправки никогда не воспроизводится**.
4. Сразу после подтверждения токенов и разрешений приложение автоматически отправляет короткий запрос через Responses API и ожидает событие `response.completed`. Один сохранённый токен не считается доказательством облачной связи.
5. Если пользователь проверяет облако без сеанса, исходная ошибка `AUTH_TOKEN_*` больше не скрывается за `CLOUD_SESSION_NO_SESSION` — причина остаётся в одном статусном сообщении, без дополнительной кнопки.
6. Защищённые записи OAuth в Android Keystore/AES-GCM и обновление refresh-токена по необходимости остаются прежними. Нет доступа к паролю, 2FA и прошлым перепискам ChatGPT.
7. Никаких новых кнопок. Вход через Custom Tab, STOP, OCR/камера и локальная стратегия сохранены. В CI повысили номер до `versionCode=75`; отталкиваемся от установленной v2.14.40 с `versionCode=74` и тем же сертификатом, что указан для v2.14.39.

## Что специально НЕ реализовано

Не добавлены локальные поля для учётных данных OpenAI, WebView, автоматическое чтение SMS/2FA или извлечение токенов из браузера: OpenAI использует официальную OAuth-авторизацию, а не передачу паролей приложению. Custom Tabs выглядит встроенным, но технически остаётся браузерным защищённым входом, как рекомендует Android.

## Проверки

- Python: **297/297** тестов, включая 6 новых проверок контракта in-app OAuth.
- OAuth Kotlin/JVM: 30 протокола, 25 облачной диагностики, 12 транспорта; отдельно прошли 6 сценариев токен-соединения, 20 проверок идентичности, 16 preflight, а также контрактные сценарии стратегического и безопасного исполнения.
- Полный старый Kotlin/JVM-прогон запускался, но не завершился в лимит; отдельные перечисленные тестовые наборы прошли.
- Android SDK/Gradle в этой среде **отсутствуют**; Android `:app:testDebugUnitTest`, `:app:assembleDebug` и реальная проверка входа через Starlink **НЕ ВЫПОЛНЕНЫ**. APK версии v2.14.41 не существует в этом результате.

## Ограничения / следующий этап

Work или совместимый Android CI должен выполнить `:app:testDebugUnitTest` и `:app:assembleDebug`, подтвердить пакет `com.example.airemote.dev`, код `75`, сертификат прежней установленной версии и SHA-256 APK. До этого **никакой установки**. Новая версия улучшает UX и проверяемость сети, но не доказывает разрешение возможных внешних ошибок DNS/серверных ограничений на конкретном устройстве.
