# AI Remote Control GPT v2.14.30 — Action Strip Evidence

**Исходники, не устанавливаемый Android APK.** Наследует v2.14.29; старый архив не перезаписывается. Оригинальное приложение 1win в оговорённом пользователем режиме условных фишек, без пополнения и вывода денег. `$` в OCR не используется как основание для остановки.

## Исправлено в этой версии

1. `ActionControlDiagnostics.kt`: после загрузки вручную измеренных `HERO_FOLD`, `HERO_CHECK_CALL`, `HERO_BET_RAISE` зон проверяет наличие надписей в правильных областях, соответствие окрашенной панели `READY`, исходный Android-пакет, размер JPEG, эпоху захвата, поколение окна, порядок кадров и их свежесть.
2. Требует минимум две различные области кнопок (включая Fold и Check/Call) и два разных согласованных OCR-кадра. Возвращает `STABLE_DIAGNOSTIC`, не `VerifiedTapArea` и не разрешение на касание. Никакой подставленной идентичности стола, раздачи или хода.
3. `OnDeviceAutomaticOcr.kt`: результат объединён с фоновым живым OCR после атомарной проверки актуальности захвата. `FrameStore` очищает его при STOP, новом JPEG, потере/перекрытии окна и сбросе сеанса.
4. `RealFrameRegionDiagnostics.kt`, `OnDeviceLayoutImport.kt`: три необязательные hero-зоны добавлены в уже существующий JSON-профиль. При добавлении hero-зон требуются все три. Недопустимая геометрия, неверные полосы и перекрытия отклоняются. В прежних профилях без hero-зон работа мест/банка не ломается, а новый модуль остаётся `NOT_CALIBRATED`.
5. `prepare_real_frame_calibration.py`: инструмент ручной разметки теперь умеет сохранять эти три области только при геометрической валидности. Ничего не угадывает по видео и не выводит fake Android package.
6. `MainActivity.kt`: кнопка отображения результата проверки полосы действий и явная готовность калибровки. `versionCode=64`, `versionName=2.14.30-action-strip-evidence`; обновлена будущая ручная GitHub Actions сборка.

## Как правильно разметить оригинальный экран

Получить реально записанный кадр и точный **applicationId оригинального 1win** с телефона, а также JPEG-разрешение службы захвата. Вручную отметить 3 прямоугольника кнопок в `boundsPixels` в масштабе **исходного 1080×2340**, по схеме:

- `HERO_FOLD`: видимая область кнопки Fold/Пас в левой трети;
- `HERO_CHECK_CALL`: физический прямоугольник Check/Call в средней трети;
- `HERO_BET_RAISE`: физический прямоугольник Bet/Raise в правой трети.

Оставить как минимум две области `SEAT_ACTION`, уже нужные стандартному профилю. Затем запустить инструмент `tools/prepare_real_frame_calibration.py` с измерениями и реальным идентификатором пакета; **координат по умолчанию нет**. Импортировать JSON через кнопку приложения после сборки APK.

`HERO_*` — **только координаты надписей в JPEG**. Они не равны координатам физического экрана и не создают пригодные для `dispatchGesture()` точки: потребуется отдельная подтверждённая привязка реального размера дисплея и области кнопки.

## Локальные тесты

- `bash tools/run_jvm_tests.sh` — полный JVM-набор прошёл, включая **31 новый тест** `ActionControlScenarios` и все старые проверки.
- `python -m unittest discover -s tools -p 'test_*.py' -q` — **230/230**, включая 8 новых Python-тестов импорта и связки.
- Добавлены 2 Gradle/JUnit-теста `ActionControlDiagnosticsJvmTest` для последующего запуска в Android CI. **Не запускались**, поскольку Android SDK/Gradle отсутствуют в текущей среде.
- Фактические жесты, точность на реальном 1win, работа установленного APK и официальный способ связи с ChatGPT **не проверены**.

## Следующие блокеры перед реально автономной раздачей

1. Источник **проверенной идентичности текущего стола и раздачи**; по значку приложения, картам и банку идентификатор не выдумывается.
2. Источник **подтверждённой очередности хода** и точного таймера; синхронизация нескольких независимых свидетельств из кадров без ложной активности при выборе предварительного действия.
3. **Координатная привязка к дисплею** с учётом системных панелей, жестовой навигации, текущего окна и действия/суммы ставки.
4. Признание изменения игрового состояния после отправленного жеста (системное `dispatchGesture` завершено != игровое действие принято). Нет слепых повторов.
5. Реальное тестирование Android-проекта (Gradle, APK, смартфон), аварийного STOP и допустимости автоматизации по правилам сервиса.

**Итог:** стало меньше слепых точек в распознавании настоящего интерфейса, но касания в реальном 1win ещё не выполнялись. Никаких недоказанных полномочий/идентификаторов не создаётся.
