# T042 Card glyph pipeline refactor, 2026-10-23

Owner asks why the application does not trivially combine rank (e.g. jack) and suit (diamond) to produce J♦. Audit confirmed that all previous readers did perform rank + suit recognition, but on one failed glyph they discarded the entire card string. In public-board/hero fusion, a separately recognized board was often retained only as a partial result. Overlay previously showed only null/complete code and hid every independently known partial glyph.

New CardGlyphChain reads the rank via the existing rank templates, reads suit via the existing two suit recognizers, checks the independently observed RED vs BLACK ink family when sufficient, and returns full code only for both compatible, confirmed glyphs. It carries a display-only partial value (В ? or ? ♦), which never satisfies the card-consensus, verified game state, or action gate. This is a single common stage for legacy, centered board, separate and adaptive hero paths. User-facing panel remains noninteractive and hides at STOP/stale capture. CenteredPlayerBoardFusion merges known pairs only when full data and the originating reported similarity supports the combined result, and retains board glyph evidence for the overlay.

Tests cover rank+suit, color incompatibility, rank/suit-only partials, complete independent hero+board, invalid combination, and UI partial glyphs. Android16 instrumentation and live screenshots are NOT evidence unless explicitly run. No increase in automatic betting permission.
