# ТЗ №048 — наблюдение за временными действиями, фишками и рубашками карт

Дата: 13.11.2026. Материал: два исходных видео, предоставленных пользователем, разрешение обоих 1080×2340. Видео не загружаются в репозиторий; кадры используются только для локальной проверки алгоритма.

## Факты, замеченные именно на видео

| Запись, позиция | Экранное наблюдение | Следствие для считывания |
|---|---|---|
| №1, ~00:40 | У игрока слева сверху временно появляется зелёное «Рейз»; перед этим местом значок фишек и **0.08**. Одновременно отдельно показан «Банк: 0.15». | Нужен собственный ROI текста действия и **собственная** область `SEAT_CONTRIBUTION` для каждого сидящего человека. |
| №1, ~00:40 → 00:46 | Справа сверху временное «Фолд», рубашки синих карт рядом с аватаром пропадают. Вклад **0.02** может оставаться виден до очистки ставок. | Связывать фолд сразу с несколькими кадрами: метка + исчезновение **своих** рубашек; не трактовать отсутствие рубашек как доказательство личности/фолда без действия. |
| №1, ~00:56 | Открыт флоп, прежние вкладки на местах визуально собраны, надпись «Банк: 0.26», фишка в центре. | Сохранять центральный банк как отдельное **отображаемое** поле, не суммировать его со ставками у игроков (возможен двойной учёт). Смена улицы помогает определить сбор ставок, но не доказывает результат раздачи. |
| №2, ~00:48 | Внизу справа рядом с аватаром временное «Рейз», перед игроком **0.06**, HERO предложен «Колл 0.06». | Проверять согласованность размера чужой ставки с надписью и текущим количеством карт/ходом. |
| №2, ~01:36 | Окно ручного рейза открывается поверх стола, часть соседних зон может быть перекрыта. | Во время оверлея или неподтверждённой геометрии возвращать UNKNOWN, а не нулевую ставку или исчезнувшие карты. |

## Реализовано в коде

- `RealFieldRole.SEAT_CARD_BACK`: новая **опциональная**, отдельно измеренная область синей рубашки карт возле конкретного аватара. Она не должна включать сам бирюзовый круг аватара: из двух видео видно, что похожий синий/зелёный цвет может дать ложное совпадение. Калибровка загружается тем же JSON-инструментом, что и другие `SEAT_*` области.
- `T048CardBackColor`: дешёвая проверка доли синих пикселей в этой области. Значения с недостаточной достоверностью остаются **UNKNOWN**; не создавать фолд из пропавших OCR-строк.
- `OnDeviceSeatRoundVisualDiagnostics`: принимает только JPEG с совпавшими `sourcePackage / captureEpoch / windowGeneration / frameSequence / размеры`, читает `SEAT_CONTRIBUTION`, `SEAT_STACK`, `POT`, `SEAT_ACTION` и измеренные рубашки. Центральный банк, суммы рядом с игроками, наличие карт и временная надпись — **разные поля одного кадра**.
- `T048SeatSignalFusion`: соединяет два снимка одного окна; выдаёт **диагностические** наблюдения `RAISE_WITH_SEAT_CHIPS`, `FOLD_WITH_BACKS_DISAPPEARING`, `BETS_MOVING_TO_CENTER`. Для рейза нужны надпись + увеличение вклада места + видимая рубашка; для фолда — надпись + переход рубашки `есть→нет`; для сборки ставок — переход борда и изменение центрального банка. Выбор конкретной карты соперника недоступен.
- Никакие T048-кандидаты НЕ превращаются в `T047SeatActorProof`, `ConfirmedOpponentAction`, разрешение на жест или автоматическую запись статистики.
- `FrameStore.lastSeatRound` показывает последнюю объединённую диагностику. STOP, смена окна, ошибки OCR и перекрывающие меню сбрасывают наблюдения.
- В Android добавлена кнопка **«1WIN — ФИШКИ, РУБАШКИ КАРТ И ВРЕМЕННЫЕ ДЕЙСТВИЯ»**: суммы у мест, центральный банк, действия и совпавшие признаки с явным предупреждением об уровне достоверности.

## Что важно для будущего этапа

1. В существующем захвате Android `OnDeviceAutomaticOcr` запускается примерно раз в 1.5 с, а JPEG обновляется с минимальным шагом около 1.8 с. На видео ярлык «Рейз/Фолд» может появляться на короткое время. **Нужен отдельный быстрый 200–400 мс измеритель временных цветных ярлыков + адаптивное OCR**, иначе часть действий будет пропущена. Пока этот высокочастотный путь не реализован — не обещать полное наблюдение без потерь.
2. Из двух видео получены ориентиры для **1080×2340**, но фактический MediaProjection JPEG может быть уменьшен. Нельзя вшивать старые координаты как готовую live-калибровку; требуется загрузить измеренные ROI под конкретные `frameWidth × frameHeight` и проверить package/window.
3. Синий пиксель сам по себе НЕ означает две настоящие карты, особенно возле бирюзовых аватаров; нужны шаблон формы, движение, несколько кадров и отрицательные примеры.
4. Слово «Банк» не означает, что фишки уже визуально перемещены с мест. Не высчитывать банк прибавлением этих фишек и не считать отсутствие суммы у места нулём.
5. Перед открытием полноценной игры нужны подтверждённые hand/turn identity и реальные actor→seat события для T047. T048 остаётся **диагностическим**, пока не завершён этот источник и тестирование на Samsung.

## Приёмка
- Фолд: на видео 1 среди ~40→46 s T048-кандидат только при наличии прежних рубашек в области того же игрока, нового их отсутствия и совпадающей подписи.
- Рейз: на видео 2 около 48 s наблюдается вклад 0.06 у конкретного правого нижнего игрока; центральная сумма не принимается за его личную ставку.
- Пот: 0.15 и 0.26 — разные последовательные показания; ни в одном моменте сумма банка не увеличивается искусственно за счёт повторного прибавления ставки.
- Нет калибровки, overlay, STOP, межоконный переход, слишком старый кадр → нет автоматических действий/доказанных событий.
- GitHub CI компиляция и JVM тесты; испытание смартфона отдельно.
