# ТЗ №045.1 — доставка данных через Sign in with ChatGPT (без API-ключа)

Дата: 2026-11-13. Основа: ТЗ №045 / PR №8. Требование пользователя: использовать уже установленный вход ChatGPT и исключительно выделенный пользователем лимит подписки. Не использовать отдельный API-ключ, не подменять endpoint на ChatGPT web/backend-api и не осуществлять автоматические действия при ошибках.

## Подтверждённый официальный канал

OpenAI поддерживает `Sign in with ChatGPT` для локальных open-source клиентов. После OAuth (PKCE) и явного согласия на `chatgpt.tokens.use.direct` клиент вправе использовать включённый лимит подписки для допустимых запросов. Технический сетевой интерфейс — **POST https://api.openai.com/v1/responses**, но авторизация — OAuth access token, а не API key. Для этого специального режима обязательны `store:false` и `stream:true`.

Официальные источники:
- https://developers.openai.com/siwc/token-sharing-open-source
- https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference
- https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites

Это не доступ к истории ChatGPT и не продолжение текущего чата. Сообщения API не сохраняют модельную память: каждое игровое решение должно заново включать актуальный контекст.

## Фактически реализовано

- `ChatGptAuthProtocol` и `ChatGptCloudBridge` **сохранены**. Они уже выполняют PKCE/OAuth, проверяют ID token/разрешённые scopes, хранят токены в Android Keystore и отправляют streaming Responses.
- `ChatGptCloudBridge.planUsageAuthorized()` отделяет сам факт входа от разрешения на расход подписки. Нет `chatgpt.tokens.use.direct` → никаких запросов.
- `ChatGptPlanHandoffProtocol` составляет ограниченную (до 1600 символов всего запроса) обезличенную сводку только из разрешённых метрик каждого экранного места (`seat_1:VPIP=43,PFR=17`), без имён/балансов/паролей и управляющих команд. Невозможные значения и незнакомые поля отклоняются.
- `ChatGptCloudBridge.sendSessionContext()` использует **ровно существующий `requestModelText`**: тот же OAuth bearer, актуальный список моделей, обработку `response.completed`, STOP/сбойные сообщения. Проверяется nonce и контрольный ответ; подтверждение означает только факт одной доставки, не постоянную память модели и не разрешение игрового касания.
- `OnDeviceOneWinPostSeatStudy` после завершённого обхода соперников делает **не более одной автоматической попытки** передачи в рамках конкретной подтверждённой посадки. При ошибке или превышении квоты повторного запроса нет. Кнопка UI позволяет оператору вручную проверить канал и увидеть диагностический результат.
- `OnDeviceVerifiedGptTurnRequests.schedule()` использует `planUsageAuthorized`; при каждом *независимо подтверждённом* ходе GPT уже получает `T043GptDecisionContract` с картами, банком, лимитами, математикой и актуальной сеансовой статистикой соперников. Данные из OCR не подменяют проверенное состояние.
- При достижении лимита ChatGPT ответ отклоняется (например, HTTP 429), без отдельного списания API. Запросы не повторяются вслепую.

## Не считать завершённым

- Успешное подтверждение OAuth на конкретном Samsung и факт выдачи scope `chatgpt.tokens.use.direct` нельзя проверить из GitHub.
- Реальную доставку пакета и получение nonce-ACK можно подтвердить лишь после запуска сборки на устройстве с уже авторизованным аккаунтом.
- Независимый механизм подписанной идентичности hand/turn и реальная исполняемость всех poker-касательных действий ещё не подтверждены — наличие транспорта не гарантирует профессиональную автономную игру.
- При `store:false` модель не запоминает предыдущий запрос. Устойчивое накопление знаний должно оставаться в локальном SQLite и перезапрашиваться контекстом.

## Что требуется проверить на устройстве
1. В настройках облачной модели приложения должно отображаться успешное подключение ChatGPT и разрешение использовать лимит подписки.
2. После завершения обхода соперников статус `CONTEXT_ACK` подтверждает разовую передачу; `CONTEXT_NOT_DELIVERED` означает, что отправка или обработка не подтверждена. По умолчанию повторных запросов не делаем.
3. В доступных моделях должен быть выбран модельный slug из `/v1/models` текущего авторизованного аккаунта. Журнал фиксирует только публичный статус/ID запроса, не токены.
4. При очередном **подтверждённом** ходе контракт T043 обязан включать карточки, банк, допустимые действия и актуальный сеансовый OCR-контекст, если тот помещается в ограниченный размер запроса.
5. Никакое подтверждение доставки данных само по себе не даёт разрешения на ставки, гарантии выигрыша или доступа к разговору ChatGPT, в котором ведётся эта разработка.
