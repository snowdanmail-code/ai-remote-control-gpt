# ТЗ №046 — адаптивное мышление ИИ-покериста и память соперников

**Дата:** 13.11.2026. **Основа:** PR №8 / ТЗ №045. Это описание фактической реализации и незакрытых требований. Примеры — условные игровые фишки.

## 1. Как строятся решения

ИИ получает не бесконечную историю чата, а ограниченную фактами **модель мира**:

1. **Наблюдение:** положительно распознанные карты HERO, борд, банк, стек, допустимые действия, текущий ход и его время.
2. **Локальная память:** наблюдения о соперниках и история завершённых раздач — в Android. Активная сессия фиксирует экранное место, локальный никнейм, статистику окна игрока и временный псевдоним.
3. **Стратегический анализ ChatGPT:** несколько правдоподобных диапазонов соперника и реакций на действия, исходя из VPIP/PFR/3bet, количества наблюдений, динамики игры, математических порогов и неопределённости. GPT возвращает структурированный вариант действия, не команды Android.
4. **Детерминированный барьер:** сравнение с реальными легальными действиями/суммами и свежим подтверждённым hand/turn/window; при расхождении не выполняется жест.
5. **Проверка и обучение:** независимое подтверждение действия, затем обновление локальных счётчиков только после достоверного окончания раздачи.

Нет гарантии, что ChatGPT «думает как человек», обладает сознанием или будет играть прибыльно. Здесь «мышление» = адаптивное моделирование вероятностей и неопределённости, не перебор комбинаций и не чтение скрытых карт.

## 2. Исправленная модель идентичности и памяти

Реализованы `T046TableOpponentMemory`, `T046TableSession`, `T046PopupObservation`, `T046OpponentSeatMemory`.

- **Сессионный ключ:** `package + captureEpoch + windowGeneration`. При смене окна/сеанса старые экранные привязки не используются.
- **Постоянные признаки в локальной памяти текущего стола:** `seatIndex`, `nickname` (если распознан), статистика из дважды распознанного popup, сессионный `P1/P2/...`. Никнейм не отправляется через облачный OAuth.
- **Связь с облачными данными:** единый псевдоним `seat_2` для статистики и состояния данной раздачи. Это место, а не постоянный ID человека. После смены человека в кресле память не должна автоматически переходить к новому игроку.
- **Смена никнейма в том же месте без подтверждённой пересадки:** пометка `ambiguousIdentity` и сброс статистики; не утверждать, что это старый или новый игрок.
- **Подтверждённая пересадка:** метод `confirmedSeatTurnover()` меняет локальный псевдоним и обнуляет прежние статистику/никнейм. **Живой производитель достоверной последовательности vacancy→arrival ещё отсутствует.**
- **Раздача:** `beginVerifiedHand()` сбрасывает статусы участия для новой достоверно установленной раздачи. Ни присутствие аватара, ни OCR-фолд не гарантируют участия.
- **Статусы:** `UNKNOWN`, `ACTIVE_CONFIRMED`, `FOLDED_CONFIRMED`, `LEFT_TABLE_CONFIRMED`. События принимаются только из специально подтверждённого источника; фолд ≠ уход со стола, подтверждённый фолд не превращается в активное участие до следующей раздачи.
- **Покрытие:** в запросе `roster_unverified=1`, пока не доказана полнота состава стола. Даже `unknown=0` среди изученных профилей не означает, что все места проверены.
- **Долговременная память:** существующий SQLite `AndroidHandLearningStore` сохраняет только достоверно завершённые раздачи с доказанной identity. Никнейм/место сами по себе не разрешают слияние между столами или днями.

## 3. Какой небольшой контекст передаётся ChatGPT

Например, при подтверждённых событиях текущей раздачи:

```text
session_popup_ocr_only=seat_2:VPIP=43,PFR=17,HANDS=200;seat_3:VPIP=15,PFR=12,HANDS=150
hand_participation_verified_only=active=seat_2;folded=seat_3;left=;unknown=1;roster_unverified=1
```

Это только два небольших поля в уже существующем `T043GptDecisionContract`, который добавляет реальные карты, банк, legal_actions и локальную проверенную математику. **При отсутствии независимых игровых событий будет `unknown`, не выдуманные `active/folded`.**

Для краткого GPT-контекста у статистики приоритет `VPIP, PFR, HANDS, THREE_BET`; `HANDS` позволяет не переоценивать недостаточную выборку. Разовый handshake может включать до 11 числовых показателей. Данные облака не используются как постоянная память: контекст формируется заново для каждого проверенного хода.

## 4. Уже внесено

- Чистый Kotlin модуль `T046TableOpponentMemory.kt` без Android/OCR зависимостей, с обязательными session/hand/event ключами.
- Интеграция popup-профилей в `OnDeviceOneWinPostSeatStudy` после подтверждённой посадки, очистка на смену сессии/STOP.
- `T043GptDecisionContract` передаёт `hand_participation_verified_only` только после независимой проверки hand/turn, исключает инъекции и не даёт модели разрешения на жест.
- `OnDeviceVerifiedGptTurnRequests` передаёт поле через существующий ChatGPT OAuth подписки, не через отдельно оплачиваемый API-ключ.
- Операторская диагностика на Samsung показывает локально никнейм, привязку к месту, сессионный alias, статус участия и прочитанные метрики.
- Unit-тесты на смену ника, смену игрока, фолд≠выход, отсутствие OCR→verified перехода, повтор событий, stale window/hand и компактный GPT пакет.

## 5. Ещё предстоит до полноценной автономной игры

- Надёжное подтверждение **кто именно занимает каждое место** при скрытии профиля, анимациях, пересадке, новых игроках и поворотах UI.
- Источник независимо подтверждённых live action/occupancy событий. **Сейчас он не готов**: экранный OCR `SeatVisualDiagnostics` не годится в качестве единственного доказательства фолда/выхода.
- Связка реально подтверждённых событий с `OnDeviceOneWinPostSeatStudy.acceptVerifiedParticipation()`, отметка новых раздач и раздельное обновление SQL только по verified terminal.
- Гарантия актуальных hand/turn identity и задержек облачных решений на конкретном устройстве. Ни наличие OAuth, ни успешная компиляция сами по себе не подтверждают производственный игровой цикл.
- Испытания Samsung: точность отображения мест, hand events, наличие разрешения `chatgpt.tokens.use.direct`, задержка GPT, false-positive rate и обрывов связи.

**Приёмка:** GitHub CI, затем измеренные тесты на устройстве. Ни имитация сознания, ни гарантия выигрыша не являются критериями.
