# ТЗ №047 — безопасная связка действий соперника и памяти раздачи

Дата: 13.11.2026. Продолжение ТЗ №046 в PR №8.

## Фактические компоненты до ТЗ №047
- `SeatVisualDiagnostics`: OCR вокруг калиброванных экранных мест, два независимых кадра. **Только диагностический признак**, не доказательство действительного действия и не личность.
- `SeatActionTransitionDiagnostics`: проверяет, согласуется ли OCR с независимыми изменениями в стеке, вкладе в банк и очереди ходов на **трёх кадрах**. Возвращает лишь `PLAUSIBLE_DIAGNOSTIC`, не игровой факт. В производственной сборке нет поставщика независимых `SeatStateSnapshot`.
- `LiveOpponentAwareness`: уже проверяет источник, окно, ключи table/hand/action, разные кадры, допустимые значения и дубли. Принимает только `ConfirmedOpponentAction` из независимого проверенного источника.
- `T046TableOpponentMemory`: хранит локально экранное место, псевдоним, никнейм, popup-статистику, неизвестный/активный/сбросил/ушёл.

## Что добавлено
- `T047SeatActorProof`: независимая связь исходного приложения, эпохи/окна, стола, раздачи, места, идентификатора игрока и ID подтверждённого действия.
- `T047VerifiedOpponentActionBridge.ingest`: отказывает, если нет независимого подтверждения места/источника, если ключи не совпали, место неизвестно/неоднозначно, игрок уже покинул стол или `LiveOpponentAwareness` не принял событие.
- **После принятия** существующим сборщиком событий безопасно записывает `ACTIVE_CONFIRMED` для CHECK/CALL/BET/RAISE или `FOLDED_CONFIRMED` для FOLD в память текущей раздачи. Ни OCR-кандидат, ни никнейм не имеют права самостоятельно вызвать этот переход. Подтверждение ставок/фолдов не даёт разрешения на Android-жест.
- Публичный ранее небезопасный сеттер `acceptVerifiedParticipation(... T046Evidence)` убран из постпосадочного модуля. Заменён на `ingestIndependentlyVerifiedSeatAction(context, observation, action, binding)` с проверкой foreground, STOP, независимо подтверждённых table/hand/window, сидящего HERO и `OnDeviceOpponentAwareness`.
- В GPT-резюме доступны не только `unknown=N`, но и `unknown_seats=seat_1,seat_2`. Передача никнеймов запрещена. При неизвестной полноте состава стола сохраняется `roster_unverified=1`.
- Добавлены JVM unit-тесты `T047VerifiedOpponentActionBridgeTest` и расширены `T046TableOpponentMemoryTest`: подмена окна/актора, отсутствие независимого подтверждения, ложный OCR-фолд, настоящий сборщик `LiveOpponentAwareness`, смена игрока, повторное событие.

## Рамки и что ещё НЕ сделано
1. **Нет реального поставщика независимо проверенных действий/связи actor→seat**. Он должен доказать больше, чем текст OCR: реальные изменения по месту, стабильную очередь хода, достоверный hand ID, независимые кадры, происхождение данных. Нельзя выставлять `sourceVerified=true` по наличию текста/аватара.
2. Настоящее `LEFT_TABLE_CONFIRMED` требует независимого события ухода; фолд — это только выход из раздачи.
3. Обновление долговременной SQLite статистики возможно лишь после VerifiedHandCompletionGate и удостоверенного события завершения, не от OCR-окна.
4. ChatGPT анализирует активных, сбросивших и неизвестных игроков только в рамках имеющихся подтверждённых данных. Если данные противоречат друг другу, без нового подтверждения никаких ставок.
5. CI компиляция и unit-тесты не являются доказательством работы на Samsung. APK и пилотное испытание нужны отдельно.

## Acceptance
- Нет подтверждённого связанного actor→seat? Нет записи «фолд» или «активен».
- Неверный epoch/window/hand/actionKey или дубли? Отклонено.
- Реальный `LiveOpponentAwareness` не принял событие? Память не меняется.
- Фолд не означает уход со стола; неизвестное место остаётся неизвестным.
- Формат для ChatGPT совпадает с popup-статистикой по `seat_N`, без сырого никнейма.
- Пройден GitHub Actions по HEAD; далее аппаратная верификация на Samsung.
