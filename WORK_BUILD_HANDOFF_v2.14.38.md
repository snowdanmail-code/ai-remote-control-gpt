# Финальная сборка AI Remote Control GPT v2.14.38 — одно действие в ChatGPT Work/CI

1. Использовать приложенный ZIP `AI-Remote-Control-GPT-v2.14.38-Verified-Upgrade-Ready-Sources.zip` (не старый v2.14.37). НЕ добавлять диагностические кнопки и НЕ выпускать много промежуточных APK.
2. Требуется доступ к рабочему Android SDK 35, Gradle 8.9, JDK 17 и Интернету для зависимости ML Kit. В репозитории предусмотрен `.github/workflows/android.yml` (`workflow_dispatch`). Если ошибки Android сборки — исправить код, тесты и повторить CI самостоятельно до успешного результата.
3. Исторические APK v2.14.35 и v2.14.36 имеют одинаковую подпись (сертификат SHA-256 `511567f44b5e527b8b388d0ea2a66ad30725a856ef76670c027b88c25007cd2c`) и пакет `com.example.airemote.dev`; v2.14.36 versionCode 70. Метаданные зафиксированы в `tools/reference_prior_apk_v2.14.36.json`.
4. Сам файл APK содержит только **публичный сертификат**, из него нельзя восстановить закрытый ключ. В прежней Work/CI-среде найдите сохранённый оригинальный signing keystore, выпустивший v2.14.35 и v2.14.36. **Не требуйте от владельца прислать пароль, 2FA или приватный ключ в чат.** Секреты хранить только в защищённом CI secrets.
5. В GitHub Actions должны быть настроены секреты `EXISTING_APK_KEYSTORE_B64`, `EXISTING_APK_STORE_PASSWORD`, `EXISTING_APK_KEY_ALIAS`, `EXISTING_APK_KEY_PASSWORD`. Базовые публичные package/certificate/version из архива уже внесены в репозиторий; не нужно запрашивать их у пользователя.
6. Текущий workflow: тесты Python, Android JUnit, `assembleDebug`; проверка APK (`aapt`, `apksigner` и `tools/verify_android_upgrade.py`) относительно реально сохранённого baseline; SHA-256; публикация **только в случае успеха**. Новый APK должен быть `com.example.airemote.dev`, versionCode 72, сертификат как у v2.14.36. При отсутствии прежнего ключа workflow ДОЛЖЕН завершиться без публикуемого APK.
7. Затем отдельно проверить в изолированной среде mock OAuth, успешный вход/подписание, DNS, TLS, HTTP 5xx, refresh, callback state/nonce, сетевые ответы, STOP. Никакие тестовые ответы не считать реальной работой с подпиской пользователя.
8. При окончательном успехе предоставить владельцу: **проверенный APK прямой ссылкой**, SHA-256, package/версию/сертификат, лог CI и короткую инструкцию «установить поверх, не удаляя данные». Если APK не построен или его подпись не совпадает — честно сообщить это, не давать фиктивную ссылку.
9. Выполнить реальную проверку входа на Samsung Android 16 через Starlink **только в одном финальном испытании владельцем** после прохождения CI. 2FA проходит исключительно на официальной странице OpenAI в Chrome.
