## 4. DNS, TLS и сеть: факты и гипотезы

Подтверждено по исходникам и тестам: UnknownHostException мог возникнуть при create вне retry; это воспроизведённый дефект транспорта. Не подтверждено, что именно он вызвал ошибку телефона. После возврата браузера сеть может меняться; GET200/401 не доказывает POST. System URLConnection и активный Android Network оставлены, IPv4/IPv6 не принуждаются. Сторонних DNS, proxy, HTTP token endpoint, обходов TLS/2FA нет.

CONNECT_TLS объединяет внутренние DNS/connect/TLS стадии HttpURLConnection: без отдельного resolver API нельзя честно разделить скрытые внутренние вызовы. Тип исключения сохраняется, сообщения/cause text не записываются. На телефоне новая трасса не получена; Starlink, VPN, Private DNS, proxy и Android не объявлены виновниками. Network/proxy признаки — наблюдение текущего состояния в момент попытки, не доказательство пути каждого пакета.

## 7. Что сохранено и что остаётся

MainActivity, STOP, CaptureService, AccessibilityService, AutonomousAndroidRuntime, LiveTapSafety и OperatorAutomationAuthorization побайтно совпадают с Build-Fixed. Все исходные модули сохранены, новых кнопок нет. Manifest/permissions не менялись. У main APK нет token provider; callback только loopback. Ни игровых действий, ни ослабления action/screen/operator gates не было.

Остаются блокировки и пробелы:

1. Нет прежнего private signing key. Доступ GitHub показывает только служебный профильный репозиторий; он не менялся. Для выпуска надо подключить предназначенный проектный репозиторий с прежними protected secrets EXISTING_APK_KEYSTORE_B64, EXISTING_APK_STORE_PASSWORD, EXISTING_APK_KEY_ALIAS, EXISTING_APK_KEY_PASSWORD. Ключ/пароли нельзя присылать в чат или коммитить. Если этот keystore нигде не сохранился, совместимое обновление криптографически невозможно; новый ключ не является решением.
2. Android runtime/instrumentation проверки новых lifecycle/storage изменений не выполнены. Для трёх дефектов есть явное baseline FAIL → PASS; для остальных нет полного Android red/green и fault injection. Недостаточно оснований выпускать APK.
3. Допуск частного клиента и аккаунта к SIWC plan usage не подтверждён; нужен официальный допуск или согласованный альтернативный API backend. Нет установленного фундаментального запрета Android из прочитанных страниц.
4. Не установлена корневая причина DNS/identity на реальном Samsung/Starlink. Новые traces в телефоне отсутствуют. Не утверждается, что OAuth исправлен.
5. Семантика earliest_refresh_at неизвестна; поле хранится непрозрачно. Приложение по-прежнему управляет одной регистрацией; полноценный UI нескольких аккаунтов не добавлялся.
6. Если logout совпадает с уже начавшимся token POST, поколение запрещает позднее локальное сохранение, но HTTP может завершиться удалённо. Отзыв replacement и полная отмена network I/O требуют Android интеграционного теста; удалённый отзыв не выдаётся за подтверждённый.
7. Refresh reservation намеренно консервативен: после неоднозначного исхода даже временный отказ может потребовать нового OAuth вместо reuse. Сохранённая старая запись не означает usable/cloud-connected; отображается REAUTH_REQUIRED.
8. Commit/storage hardware failure невозможно считать пройденным по pure policy тесту; реальный restart/fault injection Android остаётся непроверенным.
