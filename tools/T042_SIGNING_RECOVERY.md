# ТЗ №042 — восстановление совместимой подписи и защищённый CI-gate

**Статус:** старый закрытый signing key **найден и проверен**; защищённый GitHub Actions pipeline **подготовлен локально, но не развёрнут и не исполнен**, так как репозиторий проекта/его environment secrets не подключены. Реальный Android 16 instrumentation всё ещё NOT_RUN. Никакой APK v2.14.42 не выпущен.

## Результат восстановления ключа

- Источник: существующий частный резервный архив signing identity v2.14.35 в библиотеке пользователя. Закрытый ключ не вошёл в этот checkpoint или какой-либо выдаваемый отчёт.
- ZIP CRC: PASS; `keytool`: PrivateKeyEntry; сертификат SHA-256 `511567f44b5e527b8b388d0ea2a66ad30725a856ef76670c027b88c25007cd2c`; совпадает с подписанным APK v2.14.41.
- Контрольная криптографическая подпись **синтетического тестового JAR** тем же ключом: `jarsigner` PASS, `jarsigner -verify` PASS. **Не является Android APK runtime или apksigner v2 проверкой нового файла.**
- Новый ключ, новый сертификат и новая подпись APK не создавались.
- Резервная копия содержит тестовый ключ Android с типовыми debug credentials и не считается секретом высокой стойкости. Для временной совместимости с установленной debug-версией требуется использовать тот же закрытый ключ, ограничить доступ к резервной копии и защищённым CI secrets. Настоящий production signing identity нужно проектировать отдельно, с планом перехода, а не выдавать тестовый ключ за production.

## Исправление критичной дыры прежнего workflow

Старый `.github/workflows/android.yml` публиковал артефакт по результату компиляции и проверки подписи, не дожидаясь Android instrumentation. Кроме того, за baseline использовал v2.14.39, а source code checkpoint оставался versionCode75. Это могло выдавать неподтверждённый APK как верифицированное обновление.

Новый fail-closed `.github/workflows/android.yml`:

1. Запускается **только вручную** и с `promote_t042=true`, в защищённом GitHub Environment `android-signing`.
2. Выполняет Python, Kotlin/JVM, Android JUnit и компиляцию AndroidTest.
3. Восстанавливает существующий keystore **только из защищённых secrets** (без хранения keyfile или паролей в Git), проверяет `PrivateKeyEntry` и точный SHA-256 сертификата.
4. Требует `/dev/kvm`, запускает **Android API36** и `:app:connectedDebugAndroidTest`; любой сбой/отсутствие KVM останавливает выпуск.
5. **Только после PASS Android** в временной CI копии повышает версию 75→76 и `2.14.41`→`2.14.42-t042-controlled-test`, собирает приложение с тем же ключом.
6. `aapt`/`apksigner`/ZIP/SHA256 и `tools/verify_android_upgrade.py` проверяют exact package `com.example.airemote.dev`, cert SHA256, versionCode>75 относительно v2.14.41; только после проверки публикуется APK.
7. В конце временный файл с ключом удаляется. Никакие ключи/пароли/2FA/cookies не попадают в APK, отчёт, логи или GitHub artifact.

## Что ещё необходимо для реального исполнения

- Подключить **настоящий приватный репозиторий проекта**, а не существующий GitHub профильный репозиторий; сейчас доступен только профильный репозиторий, его не трогали.
- В repository Settings → Environments создать `android-signing`, ограничить доступ и конфигурировать 4 ранее принятых secrets: `EXISTING_APK_KEYSTORE_B64`, `EXISTING_APK_STORE_PASSWORD`, `EXISTING_APK_KEY_ALIAS`, `EXISTING_APK_KEY_PASSWORD`. Заполнить их в защищённом интерфейсе из существующей резервной копии, **не в чат, issue, git или лог CI**. Владелец вправе отдельно проверить правила хранения и удалить лишние незашифрованные копии после безопасного переноса.
- Запустить workflow вручную в KVM-capable runner без согласия на платный larger runner. Если стандартный runner не предоставляет KVM, gate будет BLOCKED; не покупать платные ресурсы без отдельного разрешения.
- Разобрать результаты 9 Android instrumentation методов (в частности lifecycle, Keystore, Custom Tab и transport). В случае провала исправить код и повторить, не загружая APK на телефон.
- Даже при полном CI PASS живые Samsung/Starlink OAuth+2FA и ответ модели остаются UNVERIFIED до отдельного реального испытания.

## Важные ограничения

Эта копия исходников содержит **только изменения release pipeline, baseline и тестов для gate** по отношению к T042 Source Checkpoint; OAuth бизнес-логику или STOP не меняли. Подготовка CI — не запуск Android runtime. Не объявлять исправление авторизации.
